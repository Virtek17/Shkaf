## Обнаруженное и исправленное

- На 320 px третья категория каталога выходила за край. Разрешён перенос ряда категорий на следующую строку.
- При переходе из состояния без таймера в предпросмотр оплаты часы могли показывать больше 10 минут до очередного тика. Выделены общие часы отображения с актуальным снимком при подписке.
- Две быстрые попытки подтверждения могли создавать разные локальные идентификаторы до следующего render. Экран оформления теперь использует один id попытки, а reducer дополнительно блокирует дубликаты.
- Переход в поддержку во время открытия ячейки теперь отменяет старую операцию; её запоздалый результат не меняет этап.
- Ошибка проверки доступности отличается от результата «товар занят» и позволяет повторить запрос.
- Web-анимация ожидания использует JS-драйвер; предупреждение о недоступном native driver устранено.
- Удалены неподключённые примеры Item API и компоненты шаблона. URL /explore сохранён как redirect в каталог. Удалена команда шаблона reset-project, сбрасывавшая исходники.

## Особенности среды проверки

После массовых переносов и одновременных запусков Metro / export возникла ошибка кэша «unknown module». Сервер был перезапущен с `--clear`, после чего прямой URL проверен повторно. При изменении модулей Context во время Fast Refresh потребовалась полная перезагрузка; определения контекстов вынесены в отдельные файлы. Чистый запуск проверен повторно.

Первый Android export упал при записи временного Hermes bytecode из-за ограничений песочницы. Повторный запуск с доступом к временному каталогу прошёл. Это не ошибка TypeScript или маршрутов приложения.

Скриншоты до переносов не сохранялись; сравнение выполнялось с существующими досками `design/rental-flow/main-flow.png`, `exception-states.png` и проверкой текущего UI. Попиксельная идентичность исходному приложению не утверждается.
